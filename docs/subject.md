## 1장 소개

철학(그리스어 philosophia, 문자 그대로 "지혜에 대한 사랑")은 존재, 지식, 가치, 이성, 정신, 언어에 관한 일반적이고 근본적인 질문을 연구하는 학문입니다. 이런 질문은 흔히 분석하거나 풀어야 할 문제로 다루어집니다. 이 용어는 피타고라스(기원전 570년경 ~ 495년경)가 만든 것으로 추정됩니다. 철학의 방법에는 질문하기, 비판적 토론, 합리적 논증, 체계적 서술이 있습니다.

고전적인 철학 질문으로는 "무엇이든 참으로 알고 증명할 수 있는가?", "가장 실재하는 것은 무엇인가?" 등이 있습니다. 철학자들은 더 실용적이고 구체적인 질문도 던집니다. "가장 좋은 삶의 방식이 있는가?", "(들키지 않을 수 있다면) 정의로운 쪽과 부정의한 쪽 중 어느 쪽이 더 나은가?", "인간에게 자유 의지가 있는가?" 같은 질문입니다.

역사적으로 '철학'이라는 용어는 모든 지식 체계를 가리켰습니다. 고대 그리스 철학자 아리스토텔레스의 시대부터 19세기까지 "자연 철학"은 천문학, 의학, 물리학을 아울렀습니다. 예를 들어 뉴턴이 1687년에 쓴 "자연 철학의 수학적 원리"는 나중에 물리학 책으로 분류되었습니다.

19세기에 근대 연구 대학이 성장하면서 학문으로서의 철학과 다른 분야들은 전문화되고 세분화되었습니다. 현대에는 전통적으로 철학의 일부였던 일부 연구가 심리학, 사회학, 언어학, 경제학 같은 별도의 학문 분야가 되었습니다.

예술, 과학, 정치 등 다른 활동과 밀접하게 관련된 연구는 철학의 일부로 남았습니다. 예를 들어 아름다움은 객관적인가 주관적인가? 과학적 방법은 여럿인가 하나뿐인가? 정치적 유토피아는 희망찬 꿈인가 절망적인 환상인가? 학문으로서의 철학의 주요 하위 분야에는 형이상학("실재와 존재의 근본적 본성을 다루는" 분야), 인식론("지식의 본성과 근거 [그리고]... 그 한계와 타당성"에 관한 분야), 윤리학, 미학, 정치 철학, 논리학, 과학 철학이 있습니다.

## 2장 공통 지침

- 프로젝트는 C로 작성해야 합니다.
- 프로젝트는 Norm에 맞게 작성해야 합니다. 보너스 파일이나 함수가 있다면 그것도 norm 검사에 포함되며, norm 오류가 있으면 0점을 받습니다.
- 함수는 정의되지 않은 동작(undefined behavior)을 제외하고는 예기치 않게 종료되어서는 안 됩니다(segmentation fault, bus error, double free 등). 이런 일이 생기면 프로젝트는 동작하지 않는 것으로 간주되어 평가에서 0점을 받습니다.
- 힙에 할당한 메모리는 필요한 시점에 모두 제대로 해제해야 합니다. 메모리 누수는 용납되지 않습니다.
- 과제에서 요구하는 경우, cc를 사용해 `-Wall`, `-Wextra`, `-Werror` 플래그로 소스 파일을 요구된 결과물로 컴파일하는 Makefile을 제출해야 합니다. 또한 Makefile은 불필요한 relink를 해서는 안 됩니다.
- Makefile에는 최소한 `$(NAME)`, `all`, `clean`, `fclean`, `re` 규칙이 있어야 합니다.
- 프로젝트의 보너스를 제출하려면 Makefile에 `bonus` 규칙을 포함해야 하며, 이 규칙은 필수 파트에서 허용되지 않는 여러 헤더, 라이브러리, 함수를 추가합니다. 과제에서 달리 명시하지 않는 한 보너스는 `_bonus.{c/h}` 파일에 두어야 합니다. 필수 파트와 보너스 파트는 별도로 평가합니다.
- 프로젝트에서 libft 사용이 허용된다면 libft의 소스와 Makefile을 `libft` 폴더에 복사해야 합니다. 프로젝트의 Makefile은 libft의 Makefile로 라이브러리를 먼저 컴파일한 다음 프로젝트를 컴파일해야 합니다.
- 프로젝트를 위한 테스트 프로그램을 만들기를 권장합니다. 이 작업은 **제출할 필요가 없고 채점되지도 않지만**, 자신의 작업과 동료의 작업을 쉽게 테스트할 기회를 줍니다. 특히 디펜스 중에 이런 테스트가 유용합니다. 디펜스 중에는 자신의 테스트나 평가 대상 동료의 테스트를 자유롭게 사용할 수 있습니다.
- 배정된 Git 저장소에 작업을 제출하세요. Git 저장소에 있는 작업만 채점됩니다. Deepthought가 채점을 맡은 경우, 동료 평가가 끝난 뒤에 채점이 이루어집니다. Deepthought 채점 중 작업의 어느 부분에서든 오류가 발생하면 평가가 중단됩니다.

## 3장 개요

이 과제를 성공적으로 끝내기 위해 알아야 할 핵심 사항은 다음과 같습니다.

- 한 명 이상의 철학자가 둥근 탁자에 앉아 있습니다. 탁자 가운데에는 큰 스파게티 그릇이 있습니다.
- 철학자들은 번갈아 먹고, 생각하고, 잠을 잡니다. 먹는 동안에는 생각하거나 자지 않고, 생각하는 동안에는 먹거나 자지 않으며, 당연히 자는 동안에는 먹거나 생각하지 않습니다.
- 탁자에는 포크도 있습니다. **포크의 수는 철학자의 수와 같습니다.**
- 포크 하나로 스파게티를 먹는 것은 비현실적이므로, 철학자는 먹기 전에 오른쪽 포크와 왼쪽 포크를 모두 집어야 합니다.
- 식사를 마친 철학자는 포크를 탁자에 내려놓고 잠을 자기 시작합니다. 깨어나면 다시 생각하기 시작합니다. 철학자가 굶어 죽으면 시뮬레이션이 멈춥니다.
- 모든 철학자는 먹어야 하며 절대 굶어서는 안 됩니다.
- 철학자들은 서로 소통하지 않습니다.
- 철학자들은 다른 철학자가 곧 죽을지 알지 못합니다.
- 말할 필요도 없이, 철학자는 죽지 않도록 해야 합니다!

## 4장 공통 규칙

필수 파트용 프로그램 하나와 (보너스 파트를 하기로 했다면) 보너스 파트용 프로그램 하나를 작성해야 합니다. 두 프로그램 모두 다음 규칙을 따라야 합니다.

- 전역 변수는 금지입니다!
- 프로그램은 다음 인자를 받아야 합니다.

  ```text
  number_of_philosophers time_to_die time_to_eat time_to_sleep [number_of_times_each_philosopher_must_eat]
  ```

  - `number_of_philosophers`: 철학자의 수이자 포크의 수입니다.
  - `time_to_die` (밀리초): 철학자가 마지막 식사를 시작한 시점 또는 시뮬레이션 시작 시점부터 `time_to_die` 밀리초 안에 식사를 시작하지 못하면 죽습니다.
  - `time_to_eat` (밀리초): 철학자가 먹는 데 걸리는 시간입니다. 이 시간 동안 포크 두 개를 들고 있어야 합니다.
  - `time_to_sleep` (밀리초): 철학자가 잠을 자는 데 쓰는 시간입니다.
  - `number_of_times_each_philosopher_must_eat` (선택 인자): 모든 철학자가 최소 `number_of_times_each_philosopher_must_eat`번 먹으면 시뮬레이션이 멈춥니다. 지정하지 않으면 철학자가 죽을 때 시뮬레이션이 멈춥니다.
- 각 철학자는 1부터 `number_of_philosophers`까지의 번호를 가집니다.
- 1번 철학자는 `number_of_philosophers`번 철학자 옆에 앉습니다. 그 외 N번 철학자는 N - 1번 철학자와 N + 1번 철학자 사이에 앉습니다.

프로그램 로그에 관한 규칙은 다음과 같습니다.

- 철학자의 모든 상태 변화는 다음 형식으로 출력해야 합니다.
  - `timestamp_in_ms X has taken a fork`
  - `timestamp_in_ms X is eating`
  - `timestamp_in_ms X is sleeping`
  - `timestamp_in_ms X is thinking`
  - `timestamp_in_ms X died`

  `timestamp_in_ms`는 현재 타임스탬프(밀리초)로, `X`는 철학자 번호로 바꿉니다.
- 출력되는 상태 메시지는 다른 메시지와 겹쳐서는 안 됩니다.
- 철학자의 죽음을 알리는 메시지는 실제로 죽은 시점부터 10ms 안에 출력되어야 합니다.
- 다시 말하지만, 철학자는 죽지 않도록 해야 합니다!

> **주의:** 프로그램에 데이터 레이스(data race)가 있어서는 안 됩니다.

## 5장 필수 파트

| 항목 | 내용 |
| --- | --- |
| 프로그램 이름 | `philo` |
| 제출 파일 | `philo/` 디렉터리의 Makefile, *.h, *.c |
| Makefile | NAME, all, clean, fclean, re |
| 인자 | `number_of_philosophers time_to_die time_to_eat time_to_sleep [number_of_times_each_philosopher_must_eat]` |
| 허용 외부 함수 | memset, printf, malloc, free, write, usleep, gettimeofday, pthread_create, pthread_detach, pthread_join, pthread_mutex_init, pthread_mutex_destroy, pthread_mutex_lock, pthread_mutex_unlock |
| libft 허용 | 아니오 |
| 설명 | 스레드와 mutex로 구현하는 Philosophers |

필수 파트의 구체적인 규칙은 다음과 같습니다.

- 각 철학자는 별도의 스레드로 표현해야 합니다.
- 철학자 한 쌍 사이마다 포크가 하나씩 있습니다. 따라서 철학자가 여럿이면 각 철학자의 왼쪽과 오른쪽에 포크가 하나씩 있습니다. 철학자가 한 명뿐이면 포크 하나에만 접근할 수 있습니다.
- 철학자들이 포크를 중복으로 집지 못하도록, 각 포크의 상태를 mutex로 보호해야 합니다.

보너스 파트 프로그램은 필수 파트 프로그램과 같은 인자를 받습니다. 공통 규칙 장의 요구사항을 따라야 합니다.

보너스 파트의 구체적인 규칙은 다음과 같습니다.

- 모든 포크는 탁자 가운데에 놓입니다.
- 포크는 메모리에 상태를 갖지 않으며, 사용 가능한 포크의 수를 세마포어로 표현합니다.
- 각 철학자는 별도의 프로세스로 표현해야 합니다. 단, 메인 프로세스는 철학자 역할을 해서는 안 됩니다.

> **주의:** 보너스 파트는 필수 파트가 완벽할 때만 평가합니다. 완벽하다는 것은 필수 파트가 빠짐없이 구현되었고 오동작 없이 동작한다는 뜻입니다. 필수 요구사항을 모두 통과하지 못하면 보너스 파트는 전혀 평가되지 않습니다.

## 7장 제출과 동료 평가

평소처럼 Git 저장소에 과제를 제출하세요. 디펜스 중에는 저장소 안의 작업만 평가됩니다. 파일 이름이 올바른지 꼭 다시 확인하세요.

- 필수 파트 디렉터리: `philo/`
- 보너스 파트 디렉터리: `philo_bonus/`

평가 중에 간단한 **프로젝트 수정**을 요청받을 수 있습니다. 사소한 동작 변경, 몇 줄의 코드 작성이나 재작성, 추가하기 쉬운 기능 등이 해당합니다.

이 단계가 **모든 프로젝트에 적용되는 것은 아니지만**, 평가 가이드라인에 언급되어 있다면 대비해야 합니다.

이 단계는 프로젝트의 특정 부분에 대한 실제 이해를 확인하기 위한 것입니다. 수정은 원하는 개발 환경(예: 평소 쓰는 환경)에서 할 수 있으며, 평가의 일부로 별도의 시간 제한이 정해지지 않았다면 몇 분 안에 할 수 있는 수준이어야 합니다. 예를 들어 함수나 스크립트를 조금 수정하거나, 출력을 바꾸거나, 새 정보를 저장하도록 자료구조를 조정하는 것 등을 요청받을 수 있습니다.

세부 사항(범위, 대상 등)은 **평가 가이드라인**에 명시되며, 같은 프로젝트라도 평가마다 다를 수 있습니다.
